# Part 10 health backend foundation

Health collection is disabled by default. `HEALTH_COLLECTION_ENABLED=false` leaves `GET /v1/users/me/health` available but returns `503` for source connection, summary upload, and enabling Coach context. Do not enable the flag until the revised privacy policy, iOS capability/disclosures, and platform release declarations are approved. The backend does not verify OS permission: a connected source is only PrimeRep's consent state.

All endpoints are authenticated and use camelCase. `POST /v1/users/me/health/sources` accepts `{source, readEnabled, exportEnabled}` and returns `connectionRevision`. Sources are `apple_health` and `health_connect`. `PUT /v1/users/me/health/preferences` accepts `{primarySource, coachEnabled}`. `PUT /v1/users/me/health/days` accepts `{source, connectionRevision, days}`; each day has `localDate`, `timeZone`, nullable `steps`, and nullable `asleepMinutes`. A client rebuilding a timezone/DST-affected window can additionally pass `replaceWindow: {startDate, endDate, timeZone}` (at most 35 days), including an empty `days` array to clear prior data. The server replaces an older timezone row for the same source/local date even without a replacement window; use the window when travel changes which dates exist. Uploads are idempotent, limited to the rolling 90-day window, and rejected after a disconnect or revision change. `DELETE /v1/users/me/health/sources/{source}` deletes that source's summaries and keeps a revision tombstone. A selected primary source is required before enabling Coach use.

Run `python -m scripts.purge_health_days` once daily in the production scheduler. Request-time reads/uploads also prune the requesting user's expired rows, but the scheduled job is required to delete expired data for inactive users. It logs only an aggregate deletion count. Exports include retained summaries in `account.json` and `health-days.csv`; blank cells mean no recorded value, not zero.

The Health privacy wording was approved by Diego on 2026-10-02 and is preserved in the frontend's `docs/part10-health-privacy-approved-draft.md`. It is not yet published or active in the app. A public policy URL, verified privacy contact, and production retention schedule remain pending. The existing `PRIVACY_VERSION` stays unchanged to preserve signup compatibility. Before enabling collection, publish the reviewed policy, update frontend and backend versions together, and require fresh acceptance from existing users.
